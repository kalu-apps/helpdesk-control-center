# Архитектурный разбор 

---

## 1. База данных (`mockGenerator.ts`)

Чтобы данные не дублировались и приложение не зависало, база данных разделена на две структуры (по принципу реляционных таблиц):

- `tickets` — массив заявок. Каждая заявка хранит только свои параметры и ID привязанного к ней гражданина (`citizenId`).
- `citizens` — объект-словарь, где ключом является `citizenId`, а значением — полная анкета человека (паспорт, адреса, семья, образование).

### Скорость выполнения операций 

- **Слияние данных:** Когда таблица реестра выводит список, анкета гражданина подтягивается мгновенно по прямой ссылке из словаря: `citizens[ticket.citizenId]`. Это занимает константное время **O(1)**. В итоге нет завсианий при скролле.
  
- **Поиск (`useTicketStore.ts`):** Поиск по ФИО или номеру заявки идет по всему массиву за линейное время **O(N)**. Перед поиском строка ввода очищается от лишних пробелов, дефисов и переводится в нижний регистр. Это позволяет мгновенно фильтровать 100 000 строк.
  
- **Графики и счетчики (`useDashboardAnalytics.ts`):** Вся статистика для дашборда (счетчики статусов, динамика по дням, нагрузка сотрудников) считается **за один проход цикла** `forEach` по массиву заявок. Это исключает повторные расчеты и не нагружает процессор. Результаты кэшируются через `useMemo`.

## 2. Ключевые инструменты оптимизации

### Zustand — управление состоянием без лишних перерисовок

Все данные приложения вынесены из компонентов в независимое глобальное хранилище. С помощью селекторов компоненты подписываются только на нужные им данные (например, только на строку поиска или только на активную заявку). Благодаря этому при обновлении формы или вводе текста перерисовываются только измененные элементы, а не вся страница целиком.

### TanStack Virtual — для плавной прокрутки

Если отрендерить 100 000 строк одновременно, браузер упадет. Мы используем виртуализацию списков: в DOM-дереве страницы всегда создается ровно ~20 строк (столько, сколько физически видно на экране). При скролле их содержимое мгновенно подменяется, а позиция сдвигается через `transform: translateY`. Интерфейс скроллится плавно и без лагов.

### React Hook Form — изоляция ввода в больших анкетах

В карточке заявки больше 25 полей ввода. Чтобы при вводе каждой буквы в ИНН или служебную отметку не перерисовывалась вся Drawer-панель, инпуты работают через `refs`. Символы вводятся напрямую в DOM, изолированно от компонентов.

### Полезные фичи

- **Защита от повторных сохранений:** В момент нажатия на кнопку «Сохранить данные», поверх всей формы накладывается прозрачный невидимый слой с классом `pointer-events-none`. Он на уровне браузера блокирует любые клики, фокусы и ввод с клавиатуры, пока крутится спиннер отправки.
- **Умный сброс вкладок:** Переключение вкладок внутри карточки заявки изолировано. Сброс открытого раздела на дефолтную вкладку «Профиль заявителя» происходит через нативное браузерное событие `CustomEvent` строго в момент клика мышкой по новой строке таблицы.
