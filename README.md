# Система «Реестр Обращений Граждан»

Система моделирует Ситуационный Центр по работе с заявками от граждан (до **100 000+ записей**). Каждая запись несет в себе несколько таблиц с характеристиками инцидента и личными данными гражданина (документы/состав семьи/образование).

---

## Перечень ключевых технологических решений (подробнее в ARCHITECTURE.md)

- **Zustand:** Хранилище данных
- **TanStack Virtual:** Для плавного скроллинга 100 000+ строк.
- **React Hook Form:** Против пинг-лагов.
- **Recharts:** Визуализация аналитических данных.
- **Tailwind CSS:** Стилизация интерфейса.

---

## Чек-лист для тестирования функционала

Интерфейс разделен на две основные рабочие зоны, переключение между которыми доступно в левом боковом меню.

### 1. Панель аналитических данных (Главная страница)

Интерактивный дашборд рассчитывает метрики по базе данных (100 000+ объектов) за один проход цикла.

- **Переключение временных масштабов:** В виджете _«Динамика обращений»_ переключите период на **«Неделя»** или **«Месяц»**. График мгновенно перестроит шаг сетки. Даты на оси X автоматически форматируются в компактный вид для экономии места. Масштаб сохраняется в памяти стора при переходах между страницами. При клике на график данные доступны в анимированном виде.
  
- **Фильтрация категорий:** В виджете _«Нагрузка на сотрудников»_ откройте выпадающий список категорий и выберите конкретный инцидент (например, _«Нарушение графика вывоза ТКО»_). Столбчатый график пересчитает ось Y под выбранный срез. Для исключения визуального шума текстовые подписи ФИО скрыты с осей, так как они подробно расшифровываются ниже, НО при клике на график данные доступны в анимированном виде.
  
- **Контроль числовых KPI:** Таблица _«Эффективность исполнителей Ситуационного Центра»_ демонстрирует рейтинг сотрудников. Таблица динамично перестраивается в зависимости от выбранного инцидента в селекторе _«Нагрузка на сотрудников»_.

### 2. Картотека заявок и Панель детального просмотра

Экран разделен на таблицу обращений и выезжающую боковую Drawer-панель.

- **Поиск:** Введите в поисковую строку таблицы ФИО гражданина, номер заявки или дату создания. Таблица перестроится динамически. Поисковый движок стора автоматически нормализует ввод (удаляет пробелы, дефисы, приводит к нижнему регистру), обеспечивая безошибочное нахождение записей (количество записей отображается в соответствии с фильтрацией).
  
- **Просмотр заявки:** Кликните на любую строку в таблице — справа выедет Drawer-панель. Карточка **всегда по умолчанию инициализируется на вкладке «Профиль заявителя»**, выводя перед глазами ФИО, паспортные данные и другие.
  
- **Изменение параметров:** Перейдите на вкладку _«Параметры СЭД»_ внутри открытой панели. Измените _«Статус рассмотрения»_ на _«Решена»_, выберите другого _«Ответственного исполнителя»_ через кастомный поисковый селектор и нажмите кнопку **«Сохранить данные»**.
  
- **Проверка сквозного дата-флоу:**
  1. При нажатии на сохранение вся форма плавно приглушит яркость на 40%, а кнопка перейдет в статус _«Отправка...»_, блокируя повторные клики и изменения.
  2. После успешного сохранения перейдите обратно на _Главную страницу_ — вы увидите, что общие счетчики, круговая диаграмма статусов и таблица эффективности сотрудников **мгновенно пересчитали измененные вами данные**.
   
- **Защита от ошибок:** Попробуйте вручную отредактировать текстовое поле _«Контрольный срок»_ в параметрах СЭД и ввести дату из прошлого (например, вчерашний день). Система заблокирует отправку данных на сервер, подсветит поле красным цветом и выведет подсказку: _«Срок ответа не может быть раньше текущей даты»_.

## Точки улучшения

При увеличении объема базы данных до 1 000 000+ записей текущая архитектура готова к следующим оптимизациям:

1. **Многопоточные вычисления:** Фильтрации таблиц из главного потока в фоновый поток. Это полностью исключит микро-фризы интерфейса на слабых ПК.
2. **Оптимизация дашбордов:** Внедрение задержки на пересчет тяжелых графиков дашборда при частых сохранениях карточек, чтобы снизить пиковую нагрузку.
3. **Пакетные обновления:** Объединение отправки изменений по заявке и по гражданину в одну общую транзакцию внутри Zustand-стора для сокращения циклов перерисовки зависимых компонентов.
4. **Сквозная валидация по API:** Подключение внешних контуров для автоматической проверки на реальных бд при ручном вводе.

## Инструкция по развертыванию

Для запуска необходима среда выполнения Node.js (версии 18 и выше).

1.  **Установка пакетов зависимостей проекта:**
    ```bash
    npm install
    ```
2.  **Запуск локального сервера разработки Vite:**
    ```bash
    npm run dev
    ```
3.  **Компиляция сборки:**
    Включает полную статическую проверку типов TypeScript и комплексный линтинг ESLint. На выходе формируется оптимизированный, минифицированный бандл в папке `dist`:
    ```bash
    npm run build
    ```
